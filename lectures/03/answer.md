## 宿題

- 取り組んだレベル：基礎
- やったこと：

  - 比較1：`app/agent.py` の `INSTRUCTIONS` から「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」の行を消し、「LoRAとQLoRAの違いは？」と「AIE2026の講座の宿題にある「3レベル」とは何ですか？」を実行した
  - 比較2：`app/tools.py` の `search_glossary` の docstring を「query には調べたい用語を1つだけ入れる（例: "LoRA"）」から「調べたい用語をまとめて入れる（例: "LoRA QLoRA"）」に変え、「LoRAとQLoRAの違いは？」を実行した
- 結果：

  | 条件 | 質問 | ツール呼び出し | requests / tool_calls | 入力 / 出力トークン | 回答 |
  |---|---|---|---|---|---|
  | 変更前 | LoRA/QLoRA | `search_glossary('LoRA')`, `search_glossary('QLoRA')` | 2 / 2 | 1468 / 199 | 用語集の定義どおり、最後に第2回 |

  - 比較1：指示文の「必ず検索」を消しても、2つの質問とも検索してから答えた。見えた違いは入力トークンが 48 減ったことだけで、消した1行が2回のリクエストそれぞれに入らなくなった分と考えられる

- 気づき・疑問：
  - 比較1では、検索するかどうかは指示文よりもツールの docstring（「答える前に使うこと」）で決まっていたように見える。指示文と docstring で同じことを書くと、毎回トークンを使うだけになる場合がある。ただ、2つの質問を1回ずつ試しただけなので、言い回しの違う質問や、用語集にない質問では差が出るかもしれない
  - 比較2では、モデルは docstring の例（`"LoRA QLoRA"`）をそのまま query に入れていた。引数の決め方は docstring の書き方にとても素直に従う
  - 実行前は、部分一致の検索に「LoRA QLoRA」のようにまとめて渡すと見つからないと思っていた。しかし検索関数に直接渡して確かめると、`"LoRA QLoRA"`、`"LoRAとQLoRA"`、`"LoRA, QLoRA"`、`"LoRAとQLoRAの違い"` のどれでも LoRA と QLoRA の2件が返った。用語名（3文字以上）が query に含まれていても当たる条件があるためである。trace の `[tool return]` は途中で切れていて先頭の LoRA しか見えないので、こうして別に確かめる必要があった
  - まとめると呼び出しとトークンは減る。ただし、結果の上限（`MAX_RESULTS = 3`）を超える数の用語をまとめた場合や、3文字未満の用語では取りこぼすおそれがある。docstring は「呼び出しの効率」と「検索の確実さ」のどちらを重く見るかで書き方を選ぶものだと感じた。「1つだけ」と書くのは、確実さを優先した設計なのだろう
